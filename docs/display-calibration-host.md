# 主机到 Pi 的显示校正同步

桌面程序连接远程串口后，通过同一 SSH 目标访问 Pi 本机的显示 API。
需要重启桌面程序加载发送端，并运行支持 `/api/bridge/calibration` 的 Pi 服务。

## 数据与生命周期

- 发送一次 3×4 仿射矩阵，将原始 XYZ 脉冲转换为 U/V 布局坐标和 F（µm）。F 沿逻辑 Z 正方向，使用已有焦平面；不发送逐点 UVF。
- UV 和 F 独立发布：有效 LayoutMap 即可显示 UV；启用 FocusMap 即可显示 F。普通 AutoFocus 成功且未停止时，记录此次 Z 作为仅供显示的 F=0；已有 FocusMap 时优先采用焦平面。此显示参考不会启用自动跟随或改动运动用焦平面。
- 三轴同时有效继续发送 schema_version=1；仅部分有效发送 schema_version=2 和 valid_axes（U/V/F 布尔值），无效矩阵行置零。z_calibrated 与 F 是否有效一致。schema 2 需要同步更新从端接收服务及显示程序。
- 矩阵和有效轴共同计算 calibration_id，相同结果去重。
- GET `/api/bridge/status` 发现已附着且串口连接的会话。PUT/DELETE 均携带 session_id。发送器不会接管其他会话；重新连接串口会新建发送器。
- 校正关闭或缺失时撤销；原点复位、回零、比例或极性变化时清除本机映射和焦平面，并要求相应来源重新校正；新 UV 或新 F 可独立恢复，旧来源不会复用。
- 主机启动并附着桥接后明确发送 DELETE（未完成 AF/GDS bond）；Pi 同时在新会话附着时撤销旧矩阵。启动自动恢复的历史文件不直接重新启用显示，需本次新校准。
- 校准只在参数变化时传输；XYZ变化不发送UVF样本。Pi根据控制器位置缓存本地计算，静止时不按时间清屏。
- 主机断开桥接后，Pi保留内存校准并继续本地计算显示；新的主机会话、真实串口断开、坐标复位和回零撤销校准。Pi进程重启也会清除内存校准。停止发送器不会阻塞 Tk 关闭。

## 并发与故障

Tk 每 500 ms 观察本机校正配置；HTTP 在独立串行工作线程运行，变更合并，失败退避重试。SSH/curl 有超时，JSON 通过标准输入传递，错误日志不输出远程响应或凭据。

串口发送完整 D0/D3 帧前立即锁定旧校正、清除共享焦平面并排队撤销；不会在串口锁内等待 HTTP，以免阻塞急停。Pi 必须配套启用 D0/D3 完整帧检测，在转发复位命令前撤销显示矩阵。普通串口数据字节不变。

## 验证

`tests/test_display_calibration.py` 覆盖变换、比例/极性、重复发布、失败重试、重连、外部会话隔离、过期更新、分段串口帧、HTTP 阻塞期间复位/急停以及 Tk 事件接入。

测试使用假串口和假 HTTP；跨项目接收端另以 Flask 测试接口和假串口验证。未执行真实移动、回零或校正写入。

普通对焦产生的显示参考不持久化；进程重启后需重新对焦，或启用有效 FocusMap。尚未重新对焦的历史AF结果不会被自动当作当前F零点。
